# Work plan — post-generation audit

Started 2026-11-21. The app was generated by another LLM tool; this plan reviews it without changing
any product requirement (`VOICE_EXPENSE_APP_PLAN (2).md` stays the source of truth). Anything that
*would* change a requirement or the data model is flagged and waits for the user's explicit OK.

Each phase = one or more branches, each with its own PR into `staging` (never `main`).
`[x]` done · `[~]` waiting on the user · `[ ]` to do.

## Phase A — Plan
- [x] This file (`docs/work-plan`)

## Phase B — CLAUDE.md
- [x] Tighten agent rules: small logical commits with self-explanatory messages, no co-author or
      attribution lines, no filler PRs, audit → confirm → fix workflow (`docs/claude-md-refresh`)

## Phase C — Code audit (broken code, compile-time and runtime errors)
- [x] Report in `docs/AUDIT.md`: each finding with severity, file:line, impact and proposed fix
- [~] User confirms which findings to fix
- [ ] One `fix/…` branch + PR per confirmed finding (or per tightly related group)

## Phase D — UX audit
- [ ] Report in `docs/UX_AUDIT.md`: friction points, accessibility, copy, with the smallest fix for each
- [ ] User picks what to build → one branch + PR each

## Phase E — Product improvements and small side features
- [ ] Proposals added to `docs/IDEAS.md`, each tagged *in plan* / *changes plan* / *changes data model*
- [ ] User picks what to build → one branch + PR each

## Done criteria (every code PR)
`npm run typecheck` and `npx expo lint` clean; `npx expo export --platform android` for UI changes;
`docs/TASKS.md`, `PROGRESS.md`, `ISSUES.md` (and `DECISIONS.md` for deviations) updated.
