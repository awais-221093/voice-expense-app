# Decisions and deviations

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | Route folder | Routes live in `src/app/` (not `/app`) | Project template + AGENTS.md use `src/app`; plan said "suggested". |
| 2 | Default LLM model | `openai/gpt-oss-20b` on both Groq and OpenRouter (editable) | Groq retired Llama 3.x production models in Aug 2026; gpt-oss is Groq's current production model and also available on OpenRouter. Verify IDs at https://console.groq.com/docs/models. |
| 3 | `max_tokens` | 1000 instead of ~400, with `reasoning_effort: "low"` for gpt-oss models | gpt-oss is a reasoning model; reasoning tokens count against the limit and 400 truncates multi-entry output. Still cheap. |
| 4 | Append-only rule | `llmAttempts` may grow by **one or more** items per update (old items unchanged) | One processing run can record several attempts (invalid-JSON retry, transient retry, fallback provider) in the single batched write the plan requires. |
| 5 | Offline attempts | When NetInfo says offline, the queue does not call the LLM and does **not** increment `attemptCount` | Otherwise a long airplane-mode period would burn all 5 attempts and mark commands `failed`. |
| 6 | `notes` from LLM | Any non-null `notes` → command `needs_review`, notes stored as each entry's `reviewReason` | Plan routes non-PKR currency and "couldn't place" info through `notes`; prompt tells the model to keep `notes` null otherwise. |
| 7 | Dismiss failed commands | New optional command field `dismissedAt: Timestamp \| null`; "Dismiss" on a failed / entry-less row hides it from Home | Junk transcripts would otherwise stay red forever. Nothing is deleted; dashboard can still show them. |
| 8 | Retry mechanism | Retry (button or after key/model change) sets status back to `pending`, `attemptCount 0`, `nextRetryAt null`; the normal queue then processes it | One code path for all processing. |
| 9 | Writes are not awaited | Firestore writes are fire-and-forget with error logging | RN Firebase write promises resolve only after the server acks; awaiting would hang the UI offline. Local cache + listeners update instantly. |
| 10 | `spent_at` | LLM returns a date (`YYYY-MM-DD`) only; app combines it with the current local time of day | Keeps sort order natural; plan only needs day-level dates. Dates > 1 day in the future or > 366 days old are rejected (entry flagged). |
| 11 | Debug log | In-memory ring buffer (last 300 lines), mirrored to `debug-log.json` in the app's document directory (batched every 2 s) and restored on start; "Clear" on the debug screen | Updated 2026-11-21 (IDEAS dev list): survives app kills, which is when a log is most needed. `expo-file-system` is now a direct dependency. |
| 12 | Min Android | `minSdkVersion 33` via `expo-build-properties` | Plan: on-device recognition + continuous mode need Android 13. |
| 13 | Icons | `@expo/vector-icons` (MaterialCommunityIcons) | Not bundled in this template; small JS-only dependency. |
| 14 | Bottom sheet | Built on RN `Modal` (slide), no extra library | Keeps dependencies minimal. |
| 15 | Open-commands query | Home + queue use one query: `entryIds == []`, `dismissedAt == null`, `createdAt desc`, limit 50 | needs_review commands that have entries would otherwise pile up in a status-based query. `dismissedAt` is written as `null` on create so the equality filter matches. |
| 16 | Tracking docs | TASKS, PROGRESS, ISSUES, ASSUMPTIONS in `docs/`, rules in `CLAUDE.md` | User request for agentic development. |
| 17 | Android package | `com.voiceexpense.app` (confirmed by user 2026-11-13) | Must match the Android app registered in Firebase. |
| 18 | Navigation | Bottom tabs: Home · Activity · [raised mic] · Insights · Profile (user request 2026-11-13). Settings live in Profile; the gear icon is gone. | Plan had Home as the only main screen. The mic in the tab bar keeps recording one thumb-press away from every tab. |
| 19 | Activity + Insights in the app | Month history with filters/search, and a monthly breakdown (no chart library, simple bars) | User asked for richer tabs. Overlaps DASHBOARD_PLAN reports; the dashboard keeps bulk editing, exports and 12-month trends. |
| 20 | Recording scope | `RecorderProvider` above the tabs owns recorder, result card, toasts and the entry sheet | One instance for all tabs; results show wherever the user is. |
| 21 | Typed notes (IDEAS I2) | Keyboard button on Home opens "Type a note"; the text becomes a normal command with `meta.sttEngine = meta.recordingMode = "typed"` | User asked for all IDEAS (2026-11-21). Same pipeline as speech, so no new code path; the new enum values let the dashboard tell typed from spoken notes. |
| 22 | Monthly budget (IDEAS I8) | Optional `settings.monthlyBudget` (PKR, expenses only) with a progress bar on Home; set in Profile | User asked for all IDEAS (2026-11-21), knowingly overriding DASHBOARD_PLAN "budgets out of scope". One synced number, so the dashboard can show it later or ignore it. |
| 23 | Loan balances (IDEAS I9) | Optional `entries.person` (loans only); the LLM fills it (prompt v2), the edit sheet shows a Person field for loans, Insights shows all-time balances per person | User asked for all IDEAS (2026-11-21). Optional field keeps old entries valid; equality-only query (`type == loan`, `deleted == false`) needs no new composite index. Rules updated: deploy them (COMMANDS §5). |
| 24 | Daily reminder (IDEAS I6) | `expo-notifications`; on/off + hour (7–10 pm) stored in SecureStore on the phone, not in Firestore. The next 7 days are scheduled as DATE triggers; today's is dropped once an entry is logged, and the plan is rebuilt on every app start, at midnight and on change | Local notifications can't check "anything logged today?" when they fire, so the schedule is kept current instead. Default `bestEffort` delivery needs no exact-alarm permission (may be a few minutes late). Device-local prefs mean no Firestore contract change. |
| 25 | App lock (IDEAS I7) | `expo-local-authentication`; flag in SecureStore (this phone only). Locked on cold start and after 30 s in the background; full-screen `Modal` covers open sheets too; biometric with device PIN/pattern fallback. Turning it on requires a device screen lock and one successful check; turning it off also needs a check | A lock protects the device, not the account, so it isn't synced. The PIN fallback means a failed fingerprint can never lock the user out. |
| 26 | Quick start (IDEAS I10) | Android **launcher shortcut** "Record a note" (long-press the app icon) via a local config plugin (`plugins/withRecordShortcut.js`) → `voiceexpenseapp://record` → Home starts a tap-mode recording; skipped while the app lock is up | A home-screen widget or quick-settings tile needs custom Kotlin or a third-party widget library; a static shortcut gives the same one-tap start with only resources and a manifest entry, kept in CNG. Can be pinned to the home screen from the launcher. |
